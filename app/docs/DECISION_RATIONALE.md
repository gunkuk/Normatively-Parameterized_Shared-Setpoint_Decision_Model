# Decision rationale

| Choice | Reason | Limitation / check |
|---|---|---|
| Preserve historical source | Separate reproducibility from operational extensions | Full reproduction and hashes |
| All-pair max EIG | Explicit user scientific requirement | Long measured latency; no shortlist |
| Independent grid posteriors after B | Avoid hidden pooling assumptions | Unasked cells remain prior-driven |
| Continuous envelope regret search | Quadrature-only candidate optimization can miss policy plateaus | Floating-point root diagnostics and dense independent comparisons |
| Atkinson then efficiency/equity, equality, 23°C, residual seeded random | User's operational multi-objective amendment | Central-anchor benefit is an intention, not demonstrated stability/error reduction |
| Actual boundary equality maps lower | New groups have no frozen rank identity | Historical exact memberships unchanged; repeated cutpoints disclosed |
| PostgreSQL JSON snapshots + indexed scoping | Preserve evolving scientific evidence without rewriting old records | Typed API validation; not a normalized scientific warehouse |
| One queued worker | Prevent race-prone expensive parallel acquisition | Multi-process distributed execution unsupported |
| Environment-provisioned roles | Minimal local deployment | Not organizational SSO or credential lifecycle UI |

The original specification and handoff are reference contracts. Later explicit user corrections take precedence and are recorded in IMPLEMENTATION_DETAILS.md. No document instruction authorizes autonomous physical actuation or an automatic merge.
